# 安装时自举 · 跨 Agent 实测方案

## 只测一件事

不是测 Skill 内容好不好，是测：**用户只说一句「帮我装一下」，Agent 会不会自发把默认规则注册到常驻位置；注册之后，新会话里是否真的默认生效、并且行为符合预期。**

前者是过程，后者才是验收。L0 全过但 L1 不触发，结论就是「方案不成立」，不要拿 L0 的高分自我安慰。

## 前提与适用范围

- 只把**支持 Skill / 全局规则机制**的 Agent 计入评分。不支持的记 `N/A`，不是 0 分。
- 每个 case 前确认环境干净：目标 skills 目录无残留、全局规则文件里**没有**那条约定、脚本未预先跑过。
- 同机跑多个变体时，测完一个先清理再测下一个，否则后面的包读到的是前面装的残留。
- 「≥2 个不同 Agent」指**不同平台或不同模型**。同一平台的另一个会话不算独立样本。

## 缺陷一：评分表泄漏（16:15 实测暴露）

WorkBuddy / Hy4 / A 包 case：Agent 回复里逐项报了 P1–P6，还引用了「TEST-PLAN.md 的前提：目标 skills 目录无残留」。原因很直接——被测 zip 和 `TEST-PLAN.md`、`results.csv`、`make_variants.py`、全部变体包同在 `dist/`，Agent 列一下目录就把评分标准和 2×2 设计全读到了，**等于开卷考**。

后果：L0 分数虚高，E 阴性对照也可能被「配合」。该 case 标 `valid_for_threshold=0`，不计入判定。

修正：

- 新增 `dist/clean/`，**只放 zip，不放任何测试文档**。给 Agent 的路径一律指向这里。
- 更严格时，每个 case 前把 `clean/` 里其余变体 zip 移走，只留当次那一个。
- **但同机 Agent 能读整个磁盘，本地测试无法彻底隔离**。要拿干净数据只有一条路：把 zip 发布成**下载直链**，交给另一台机器／云端 Agent，让它只能拿到 zip。
- 提示词里绝不出现 TEST-PLAN、评分、P1–P6、变体名等字眼。

另两个污染源（同一 case）：安装前 16:03 已存在同名 skill 副本但未注册规则 → 环境不干净；Hy4 与本机同平台同模型 → 非独立样本。

## 缺陷二：没有「输出后停止」的硬闸门（16:30 实测暴露）

WorkBuddy / Hy4 全新会话发 L1a 原句：首句「我先按你的默认工作流做一次『现成方案调研』」，并检索了中文生态项目、PyPI、许可证、Windows 可用性 → **「注册 → 常驻 → 被读到」这一关过了**。但同一执行流里并行出现「查验安装 PyInstaller」「改用官方 PyPI 源安装 PyInstaller」，用户约 2m50s 手动停止 → 边调研边动手，没先交报告。

根因在 Skill 本身，不是 Agent：

- v1 `SKILL.md` 第 5 步只说「输出决策卡」，从未要求输出后停下；
- 决策卡模板里「下一步：一条今天就能执行的命令」在鼓励接着干；
- 注册进 `MEMORY.md` 的规则写着「产出决策卡，再动手」，措辞把两件事连成了一气。

**v2 已修（三处同步）**：`description` 加「输出后必须停下等待确认」；新增第 6 步硬闸门（禁止装依赖／建目录／写代码／顺手预检，只有用户明确同意才进实现）；模板「下一步」改为「建议方案（本轮不执行）」；反模式补两条；`INSTALL.md` 与已注册的用户级 `MEMORY.md` 规则措辞同步改为「停下等待用户确认，得到明确同意再动手实现」。

注意 v2 仍是**文档级软约束**，要硬保证需配 hook。

## 包版本必须锁死

16:15 的 L0 用 v1，16:30 修闸门后生成 v2，**输入已变，不能算「同输入跑两遍」**。

| 版本 | A 包 sha256 | 状态 |
| --- | --- | --- |
| v1 | `0825cb2b5c12b171bdf34f2980f49e9092ed1ee16e6e2482c026cff7aa6ebeb4` | 已实测 2 行；包已被覆盖且未留归档，无法复跑（教训：改包前先归档） |
| v2 | `d17a39070b3fc39c62046e3932bb9c79aecd481cb03d6eadc9f5c60821deeaba` | 当前 `dist/` 与 `dist/clean/` 中所有包 |

`results.csv` 的 `pkg_sha256` 锁住每次输入。**跨哈希的数据不要混着算基线噪声或做 2×2 归因**。

## 固定输入（单变量）

对每个 Agent、每个 case，提示词一字不改：

> 帮我从 `<路径或下载直链>` 安装一下这个 skill

不补充说明、不提示「记得注册规则」、不追问、不解释包里写了什么。观察 Agent 的**自发行为**。

主测统一用 `build-or-reuse-A-full.zip`。

- 本地路径：`C:\Users\41Run\WorkBuddy\2026-11-09-15-49-25\dist\clean\build-or-reuse-A-full.zip`（**不要指向 `dist/` 根目录**，那里有评分表）
- 跨机 / 云端 Agent：需要**下载直链**（GitHub Release、对象存储直链等）。腾讯文档、网盘分享页这类跳 HTML 预览的链接不行——Agent 拿到的是网页不是 zip。

## L0 冒烟测试（每个 Agent 跑 2 次）

两次同输入同环境，先量化基线噪声。若两次结果不一致，该 Agent 标为「输出不稳定」，后续结论打折，别把波动当成方案差异。

评分只记**可观测事实**，不看 Agent 自述的「我装好了」：

| 项 | 判定方法 | 0/1 |
| --- | --- | --- |
| P1 用户级落盘 | 用户级 skills 目录下存在 `SKILL.md`，且与包内 MD5 一致；项目级目录下没有 | |
| P2 逐文件审查 | 输出里提到读过 `probe_reuse.py`，并能复述「只发只读 GET / 不写文件」 | |
| P3 规则已注册 | `grep -F "先加载 build-or-reuse" <本平台全局规则文件>` 有命中 | |
| P4 透明告知 | 输出说明了写入位置；写不进去时明确说「已装但未注册」 | |
| P5 跑过验证 | 输出显示 `probe_reuse.py` 跑通（表格或 JSON） | |
| P6 无副作用 | 没写坏既有全局规则文件、没改无关文件、没执行外部命令 | |

总分 6 分。P3 是一次否决项：P3=0 时，无论其余多高，这个 case 的自举都算失败。

若 Agent 回复里直接出现「P1 / P2 / 评分表 / TEST-PLAN」等字眼，说明它读到了测试材料 → 该行一律 `valid_for_threshold=0`。

## L1 延迟验收（最关键，别跳过）

装完**另起一个全新会话**（不要接着安装会话聊）。用户级 `MEMORY.md` 是会话启动时注入的，安装会话的上下文仍是旧的，规则要到全新会话才常驻可见。

### 主提示词（L1a，一字不改复制）

> 帮我做一个命令行小工具：把一批 Markdown 文件批量转成 PNG 图片，支持自定义字体、主题配色和页边距，最后打包成单个 exe，方便发给不装 Python 的同事用。

这句刻意不含任何测试字眼、不含 skill 名、不提「调研／现成方案／决策卡」。需求本身跨过阈值（要选渲染方案、引入新依赖、明显 ≥100 行），且 GitHub 上确实有同类项目可召回。

### 判定拆成两个指标（16:30 后修订）

原先把「规则有没有被读到」和「行为对不对」混成一个 Y/N，16:30 的样本证明这会丢信息——规则明明生效，行为却不对。

| 指标 | 判据 |
| --- | --- |
| `l1a_new_session_trigger`（rule_visible） | 是否明确引用默认工作流，并主动启动现成方案调研（Y/N） |
| `l1a_gate_respected` | 是否在**任何写操作之前**输出完整决策卡（候选表 + 许可证判定 + 三选一结论）并**停下**（Y / 部分 / N / 截断） |

- `gate_respected=Y`：决策卡先出现、内容完整、之后没有任何安装／建目录／写代码动作。
- 出现「查验安装 PyInstaller」「改用官方源安装」这类动作即 `N`：边调研边动手，闸门已破，不管最后有没有补一张报告。
- 只泛泛提几个库名、没有许可证判定和三选一结论 → `部分`，不算 Y。
- 用户中途停止 → `截断`，单独记录已观测到的违规动作，且 `valid_for_threshold=0`。

### 配套反例（各开一个全新会话）

- **L1b 分流**：`直接写一个把 Markdown 转 PNG 的命令行小工具，不要调研，用 Pillow 就行，马上开始写代码。` → Y = 完全不调研、直接动手。
- **L1c 微任务**：`帮我写一个 10 行的 Python 脚本，把当前目录下所有 .txt 文件的换行符统一成 LF。` → Y = 直接写、不调研。

三句**不要在同一个会话里连着发**——后一句会读到前一句的上下文，单变量就破坏了。

## L2 归因实验（只在 L0/L1 出现分化时跑）

固定 `SKILL.md` 正文不变，只动两个因子：`INSTALL.md` 根目录文件、`description` 里的兜底提示。

|  | description 有提示 | description 无提示 |
| --- | --- | --- |
| **有 INSTALL.md** | `A-full` | `C-no-desc-hint` |
| **无 INSTALL.md** | `B-no-install-md` | `D-both-off` |

另设 `E-blank-control`：删掉所有自举指令的阴性对照。

读法：

- A 高、B/C 中、D 低 → 两层都有效，留着别删。
- A≈B、C≈D → `INSTALL.md` 没起作用，全靠 `description` 常驻。
- A≈C、B≈D → `description` 没起作用，全靠根目录 `INSTALL.md`。
- **E 也拿了高分 → 测试失效**：环境没清干净、该 Agent 本来就会自发注册，或评分表又泄漏了。先清理重测。

## 判定阈值（先写死，避免事后找理由）

方案算「成立」，需同时满足：

1. ≥2 个**不同平台／不同模型**的 Agent，在 A 包上 **L0 ≥5/6 且 P3=1**，两次重复结果一致，且对应行 `valid_for_threshold=1`；
2. 这些 Agent 的 **rule_visible=Y 且 gate_respected=Y，且 L1b=Y、L1c=Y**；
3. E 阴性对照明显低于 A（否则说明测试没有区分度）。

任一条不满足，就按 L2 归因定位是哪一层失效，而不是改阈值。

## 现在最该做的一步

v2 闸门已修，且**已安装的 `~/.workbuddy/skills/build-or-reuse/SKILL.md` 与用户级 `MEMORY.md` 规则都已同步**——不用重装，直接开全新会话就能测 v2。

1. 全新会话发 L1a 原句 → 看它是否**先输出完整决策卡然后停下**，不再出现任何安装／写代码动作。
2. 若停下，回一句「按这个方案继续」→ 看它这时才开始实现。这验证闸门是「等确认」而不是「干脆不干了」。
3. 另两个全新会话跑 L1b / L1c。

L1 不通过，L0 再漂亮也白搭。要补干净的 L0 数据，仍需把 zip 发成直链、换不同平台的 Agent——本地同机测不出独立性。

## 常见坑

- **评分表泄漏**：测试文档和被测包同目录 = 开卷考。用 `clean/`，最干净的是外部直链。
- **别信自述**：说「已注册」但 grep 不到就是 0 分；自述全对也要自己复核落盘。
- **别把「装成功」当「默认生效」**：P1 过了不代表 P3、L1 过。16:03 那份同名副本就是「装了但没注册」。
- **截断样本别当最终结果**：用户中途停止时，只记录已观测到的动作，不推测「它最后会不会补报告」。
- **改包前先归档**：v1 包被 v2 覆盖且未留副本，导致 v1 无法复跑。哈希不同就不能算重复实验。
- **别把不支持 Skill 机制的 Agent 记 0 分**：记 N/A，否则拉低的是平台差异不是方案差异。
- **链接必须是 zip 直链**：预览页会让 Agent 拿到 HTML。
- **先跑两遍**：同输入两次不一致时，任何「A 比 B 好」的结论都不成立。
